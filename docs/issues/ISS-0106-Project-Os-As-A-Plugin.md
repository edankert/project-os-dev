# How does the project-os mod reach each repo: generated by the template sync like the agent files, or installed from a plugin marketplace?

## Problem

The project-os mod in [[FEAT-0041-Project-Os-Mod]] has to reach all the fleet repos and stay current there. A mod always lives inside a Claude Code plugin, so the question is how that plugin is placed and loaded in each repo. Cockpit PHASE-046 suggested making project-os a plugin marketplace, so that project-os's Claude Code files would carry a version instead of being copied once. That suggestion rested on a premise that was already out of date.

## What is true today

- The template sync already refreshes `.claude/`. After a sync, `sync-project-os.py` runs `generate-adapters.py --install-hooks`. That rewrites `.claude/agents/` and `.claude/skills/` and registers the hooks in `.claude/settings.json`. `tools/sync/MANIFEST.yaml` marks both folders `generated`. This has been so since 2026-07-18 (project-os `7ffb5d5`).
- project-os-cockpit's CLAUDE.md ("Model routing") said the sync "never touches `.claude/`", and the 2026-10-08 review and this repo's reply on 2026-10-14 repeated it. It was stale and was corrected on 2026-10-14. Drift is already detected: `generate-adapters.py --check` runs at pre-commit and in CI.
- Checked on 2026-10-14: in the seven repos that have `.claude/agents/`, `planner.md` and `independent-reviewer.md` are byte-identical to the template's. The only differences in `.claude/skills/` are the repos' own skills: `cockpit-driving` in project-os-cockpit, and five iOS skills in your-trainer.

## The options

- **(a) The sync generates the plugin.** `generate-adapters.py` writes the plugin folder the way it writes the agent files, and registers it. Nothing is renamed, and no repo needs a new install step. Not yet checked: whether `.claude/settings.json` can load a plugin from a folder inside the repo without a marketplace. If it cannot, `CLAUDE_CODE_PLUGIN_DIRS` or a local marketplace entry would be needed.
- **(b) A marketplace carrying only the mod.** The mod carries a version and updates without a sync. The skills and agent files stay generated.
- **(c) A marketplace carrying everything.** Plugin skills are named `plugin:skill`, so every instruction, `CLAUDE.md` line and hook message that names a skill would need checking. A repo's own skills (the six above) would stay local files, so a repo would have two kinds of skill name. Codex does not load Claude Code plugins, so the Codex adapter keeps its current files either way.
