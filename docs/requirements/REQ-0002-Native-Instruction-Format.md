# Adapters must deliver rules in each tool's native instruction format

## Statement
Each tool adapter MUST produce instruction files in the target tool's native format, using that tool's mechanisms for loading and scoping.

## Acceptance Criteria

- [x] Claude Code adapter produces `CLAUDE.md` importing the always-active lifecycle rules and listing the rest as paths — evidence: `CLAUDE.md` carries one `@import` (`@tools/instructions/LIFECYCLE.md`) with the remaining instruction files listed as plain paths under "Reference instructions"; rationale in `tools/adapters/claude-code/ADAPTER.md` ("listed as paths (not imported) to keep context window lean").
- [x] `AGENTS.md` ships as the cross-tool generic contract consumed by Codex — evidence: `AGENTS.md` (startup contract, docs-first gate, edit boundaries); `tools/adapters/codex/ADAPTER.md` and `tools/adapters/generic/ADAPTER.md` ("`AGENTS.md` is a cross-tool convention, not Codex-specific").
- [x] Cursor adapter produces `.cursor/rules/*.mdc` with glob scoping — evidence: 8 generated files; scoped globs e.g. `snapshot.mdc:3` `["SNAPSHOT.yaml"]`, `traceability.mdc:3` `["docs/**/*.md"]`; generated by `generate-adapters.py`.
- [x] Generic fallback uses `CONTEXT.md` — evidence: `tools/adapters/generic/ADAPTER.md:20-22`, `:33`; `CONTEXT.md` present at repo root.

## Amendments (2026-07-21)

Two criteria were reconciled against the delivered design rather than ticked as written (per `tools/skills/close-out/SKILL.md`, "Requirement advancement"):

- **Criterion 1** originally required `CLAUDE.md` to carry `@import` references to *the* `tools/instructions/` files (plural, implicitly all). Shipped: exactly one `@import` (LIFECYCLE.md) with the remaining instruction files listed as plain paths, a deliberate context-window budget decision recorded in `tools/adapters/claude-code/ADAPTER.md`. Criterion narrowed to match.
- **Criterion 2** originally required a *Codex* adapter producing `AGENTS.md` "with equivalent content" to `CLAUDE.md`. Shipped: `AGENTS.md` is the **generic cross-tool** contract (not Codex-specific, not content-equivalent) — it carries the startup contract and edit boundaries rather than the instruction/skill inventory. Criterion rewritten to the delivered role.

Both departures are design decisions that predate this backfill; neither is outstanding work.
