# State model simplification

Implements ADR-0008, ADR-0009, ADR-0010 and ADR-0011, across all 10 project-os repos plus `project-os-cockpit`.

## Part 1 — taxonomy and migration

### Status vocabulary: 64 → 53 declared values

`tools/instructions/STATUSES.md` is the source of truth. Deleted where a value had **<10 writes fleet-wide and zero live notes**; kept where a value had live notes or was the only way to record a real outcome.

| Type | Change |
|---|---|
| issue | `closed` **merged into `fixed`** — one terminal status; `in-progress`, `blocked`, `reopened` deleted |
| task | `next`, `blocked` deleted; **`superseded` added** |
| phase | **`superseded` added** |
| test | `{ready, passing, failing}` — `draft`, `blocked`, `deprecated` deleted; **`ready` = defined, not yet executed** |
| risk | `mitigating`, `monitoring` deleted |
| adr | `rejected` deleted |
| release | `staged` deleted |

**Blocked-ness is now a relationship**, not a status: record `depends: [ID]`, which names *what* is blocking. **Reopening** is a transition back to `open`.

Three values were **added**, not deleted — 72 notes carried `superseded_by:` pointing at a successor feature/phase (work absorbed, not abandoned), and 8 manual tests at `active` had no truthful home in `{passing, failing}`. Details in ADR-0008's amendment.

### Migration: 190 notes + 34 snapshot entries, 10 repos

`tools/scripts/migrate-status-vocabulary.py` (new) — dry-run by default, per-repo, and it **refuses** any mapping that would move a completed work item out of completion.

### Grandfathering is now a ledger, not a date

`FEATURE_REQ_GATE_FROM` is **gone**. It compared a cutover date against each note's `updated:`, so editing a grandfathered note for any reason re-armed the gate on it — a typo fix or a template sync could break a build. Replaced by `tools/GRANDFATHERED.yaml`: an explicit, ID-named list generated by `tools/scripts/grandfather.py`. Listed items warn; everything else errors immediately. **327 entries** across 7 repos.

### Validator

- `ALLOWED_STATUS` collapsed; `TERMINAL["issues"]` is now `fixed`.
- `NOTE-STATUS` **promoted to error** and extended to *registered* notes — it previously skipped anything in `SNAPSHOT.yaml`, checking the snapshot's status rather than the note's, so the reported count was a floor rather than a census (ISS-0009).
- Feature scope-resolution accepts `superseded`.
- `metrics.issues_open` redefined.

### Cockpit

`delivered` band **retired** ([[project-os-cockpit ADR-0006]]) — ADR-0008 deleted `staged` and `monitoring`, its only two members, so it could never be entered again. `ready` moved to the pending band. Bundled validator re-synced.

## Concerns raised (per the stated constraint)

Two migrations change how an item *reads*, both corrections, both called out rather than buried:

1. **50 issues at `done` → `fixed`** (your-trainer). `done` was never a legal issue status and is absent from the cockpit's `DONE_ISS`, so these rendered as *incomplete* despite their authors marking them finished. They now read as complete.
2. **3 change notes at `active`/`draft`/`in-review` → `merged`.** All dated and landed; `{merged, reverted}` has no pre-merge state.

Neither un-completes anything. A third case — a `reference` at `complete` → `active` — was initially **refused** by the migration's own guard; the guard was over-broad (type-agnostic) and was scoped to work-item types, since that note's status described the sweep it documents, not its own lifecycle.

## Part 2 — the rest of PHASE-0002

### Executable verification (FEAT-0016)

`tools/scripts/run-tests.py` executes each `TST-*` note's `command:` and stamps `passing`/`failing`/`last_run`/`exit_code`. **Three outcomes**, not two: a command that cannot run at all (missing binary, timeout) reports `unrunnable` and leaves the status alone — conflating "the system is broken" with "my machine lacks a tool" is what teaches people to stop believing a status.

Proven end to end, not asserted: TST-0001 was stamped **`failing`** from a real non-zero exit, then `passing` once the underlying errors were fixed. Inversion verified — `exit 3` → `failing`, missing binary → `unrunnable`, status untouched.

Backfilled before promotion: **80 manual tests** given `last_verified:` (dated from each note's `updated:`, not migration day — the kinder option would have asserted verification that never happened), **49 waivers** given `waiver_expires: 2026-10-23`. 13 tests are now correctly reported stale.

### Derived state (FEAT-0015)

`sync-snapshot.py` syncs each item's `status`, `counters` and `metrics.counts` from note frontmatter — at pre-commit (re-staging the file) and in CI with `--check`. **0 drift across all 10 repos.**

It is a **surgical updater, not a generator**. The whole-file generator was built first and rejected on its own shadow run: it would have added 180 items, dropped 153 and destroyed ~80 comment lines, because a snapshot is duplication *plus curation*. Membership, retention and prose stay authored. `ITEM-STATUS`/`COUNTER`/`METRICS` are **retained** as the backstop for when the hook has not run — narrowed from ADR-0009's "deleted", on evidence.

Two bugs found and fixed in the process, both fleet-wide:
- `FEAT-0009` resolved to a *change note* (`CHG-…-FEAT-0009-…`) via substring indexing — status authority now uses real claims only.
- **Latent validator bug:** `set(str(int("0009")))` is `{"9"}`, so every zero-padded nines ID silently escaped counter integrity. Now `is_sentinel_id()`, which requires ≥3 nines and handles both `PHASE-999` and `PHASE-0999` (the fleet uses both).

### Single state contract (FEAT-0014)

`STATUSES.md` is now normative for values, gates **and who writes each status**. Every other file links to it. The `next`/`mitigating`/`monitoring`/`staged`/`reopened` references left in 6 skills were swept.

### Enforcement severity (FEAT-0017)

Full triage recorded in TASK-0069. `NOTE-STATUS`, `TEST-FIELDS` and `WAIVER` promoted to error **at zero findings** (debt cleared first, per clause 3). `REVIEW` (207 findings) gets a dated promotion — error on **2026-10-23** — via a new `PROMOTIONS` table, which is clause 2's mechanism made real.
