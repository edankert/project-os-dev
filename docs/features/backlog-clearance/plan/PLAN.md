# Delivery plan: the backlogs are cleared once

1. **your-trainer, the March batch** (ISS-0070 to ISS-0106). For each issue, find the code it names and decide which of the four states applies. Record how the 34 split across them: that split calibrates the method for everything after.
2. **your-trainer, the rest** (about 82 issues), grouped by area: BLE and trainers, workouts, Strava, billing and licensing, localisation, release and process.
3. **your-health** (65).
4. **project-os-dev** (37), starting with ISS-0033 to ISS-0039.
5. **project-os-cockpit** (35), starting with ISS-0268, ISS-0307 and ISS-0301.
6. **your-sudoku** (17), **project-os-deck** (17) and **articles** (3).
7. **One question list per repo**, handed to Edwin when that repo's leg ends.
8. **Measure again** after each leg, and update the reference note.

A fix during the cleanup is small and in one place, with a test that fails without it. Anything bigger is kept, with a plain title and a link to its feature (Edwin, 2026-09-18).

A leg does not open a new phase in its repo. It is a task in that repo's standing phase for its record, per the cockpit's ISS-0077 rule.
