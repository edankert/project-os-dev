# Reference Documentation

Use this docs area for material that supports the project but is not itself structured project-os lifecycle state.

Good fits:
- Source/reference packages copied in from elsewhere.
- Evidence policies, published collateral, supporting datasets, registries, and background material.
- Durable context that should not become active feature, task, issue, requirement, workflow, test, decision, risk, or change state.

Use the structured lifecycle directories under `docs/` when material should participate in project-os lifecycle tracking, views, traceability, or agent focus. If you need a structured explanatory note, start from `docs/__templates__/reference.md` and use `type: [[reference]]`.

Downstream projects own this area. Template sync should only add this README when `docs/reference/README.md` does not already exist.
